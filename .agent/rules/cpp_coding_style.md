# C++ Coding Guidelines

本ドキュメントは、プロジェクトのコーディングスタイル、ドキュメンテーション、および型語彙に関するルールである。一貫性、可読性、保守性、および仕様からの正確な実装導出を保証するための、明確で階層的、かつ包括的なガイドラインを提供する。

## 1. 一般原則 (General Principles)

*   **標準C/C++準拠**: 標準的なC/C++（C++20以降推奨）の原則に準拠すること。
*   **メモリ効率最優先**: 設計および実装において、メモリ効率を最優先すること。
*   **設計駆動開発**: 設計ドキュメントに準拠し、仕様から実装を導出すること。
*   **契約優先 (Contract-First)**: 外部仕様は振る舞いの契約として記述し、実装詳細（具体的なデータ型など）への依存を排除すること。
*   **トレーサビリティ (Traceability)**: 全ての設計判断は要求キーワード `{Keyword}` から導出され、逆向きの追跡が可能であること。
*   **厳密なロジック (Strict Logic)**: 曖昧な自然言語を避け、状態、条件、副作用を明確に分離して記述すること。
*   **再現性 (Reproducibility)**: シェルスクリプトや設定ファイルを含むソースコードの生成は再現性があること。

## 2. ファイル構造とインクルードガード

*   **ヘッダファイル**: `.hxx` (推奨) 。パスは `inc/` 配下を基本とする。
*   **ソースファイル**: `.cxx` (推奨) 。パスは `src/` 配下を基本とする。
*   **インクルードガード**: `#pragma once` を使用すること。従来の `#ifndef` / `#define` / `#endif` は使用しない。

## 3. 命名規則 (Naming Conventions)

*   **一般原則**: 特に指定がない限り、ほとんどの識別子に `snake_case` を使用すること。
*   **クラス、構造体、列挙型、関数、変数**: `snake_case` (例: `ipc_router`, `send_message`, `execution_context`)。
*   **インターフェース**: 純粋な `snake_case`。`i` や `I` のプレフィックス/ポストフィックスは使用しない (例: `loader_if`, `interpreter_if`)。
*   **定数、マクロ**: `UPPER_SNAKE_CASE` (例: `MAX_BUFFER_SIZE`)。
*   **列挙型定数**: `UPPER_SNAKE_CASE` (例: `RESERVED`, `READY`)。
*   **クラスのインスタンスメンバー**: `variable_` (末尾にアンダースコア1つ)。
*   **クラスの静的メンバー**: `variable__` (末尾にアンダースコア2つ)。
*   **構造体 (POD/DTO) メンバー**: `variable` (末尾にアンダースコアなし。カプセル化されたメンバーにのみアンダースコアを使用)。
*   **型接尾辞**: `_t` 接尾辞は `typedef` / `using` 宣言にのみ許可される。`struct` または `class` 名には使用しないこと。`using` エイリアスの場合は、接尾辞なしで `snake_case` ルールに従うこと。
*   **単体での意図の明確化**: クラスや構造体の名前は、単体でその役割と文脈が理解できる名前とすること。`Manager`、`Data`、`Info`、`Impl` などの一般的すぎる名前は避け、`service_manager`、`session_data`、`connection_info` のように具体的に記述すること。

## 4. 型語彙とエイリアス (Type Vocabulary)

仕様のための推奨される型語彙と、実装のための対応するC++ `using` エイリアス。

### 4.1. プリミティブ型エイリアス
| 仕様型名 (日/英) | C++ エイリアス | 基本型 | 説明 |
| :--- | :--- | :--- | :--- |
| アドレス値 / Address | `address` | `uint32_t` | メモリアドレス |
| オフセット / Offset | `byte_offset` | `uint32_t` | 基点からの相対バイト位置 |
| バイト数 / Byte Count | `byte_count` | `uint32_t` | メモリサイズまたは長さ |
| エントリ数 / Entry Count | `entry_count` | `uint32_t` | 配列・テーブルの要素数 |
| 命令カウント / Instruction Count | `instruction_count` | `uint32_t` | 実行された命令の回数 |
| 関数インデックス / Function Index | `function_index` | `uint32_t` | 関数テーブル内の位置 |
| シフト量 / Shift Amount | `shift_amount` | `uint8_t` | ビットシフト演算の量 |
| ビットフラグ / Flags | `interrupt_flags` | `uint32_t` | ビットセット |
| ブール値 / Boolean | `bool` | `bool` | 真偽値 |

### 4.2. 複合型エイリアス
| 仕様型名 (日/英) | C++ エイリアス | 基本型 | 説明 |
| :--- | :--- | :--- | :--- |
| バイナリビュー / Binary View | `binary_view` | `std::span<const uint8_t>` | ROM上の読取専用参照 |
| 可変バイナリビュー | `mutable_binary_view` | `std::span<uint8_t>` | RAM上の書込可能参照 |
| データ範囲 / Data Range | `data_range<T>` | `std::span<T>` | 特定のメモリ範囲への参照 |
| 結果型 / Result Type | `result<T, E>` | カスタム | 成功値またはリカバリー戦略を返す |
| 操作結果 | `operation_result` | `result<void, recovery_strategy>` | 値を返さない操作の結果 |
| オプショナル値 | `optional<T>` | `std::optional`等 | 値の有無を表す |
| 経済的な関数 | `economic_function<Sig>` | カスタム | ヒープレスな関数オブジェクト |

### 4.3. コンポーネント固有エイリアス (例示)
*   `wasm_pc`: WASMプログラムカウンタ (`byte_offset`)
*   `wasm_opcode`: WASM命令コード (`uint8_t`)
*   `module_id`: モジュール識別子 (`uint32_t`)
*   `task_id`: タスク識別子 (`uint16_t`)
*   `code_offset`: JITコードオフセット (`uint16_t`)

## 5. フォーマット (Formatting)

*   **インデント**: スペース2つ。タブの使用は禁止。
*   **波括弧**: `Attach` スタイル (K&R)。文と同じ行に開始波括弧を置く (`if (cond) {`)。
*   **行の長さ**: 最大100文字。
*   **ポインタ・参照**: 左寄せ (`int* p`, `const Type& obj`)。
*   **アクセス修飾子**: クラススコープ内でインデントさせない (0列目)。
*   **Clang-Format**: 機械的なフォーマットは、プロジェクトの `.clang-format` に準拠すること。

## 6. コメントとドキュメンテーション

*   **言語**: **ソースコード内（コメント、ログ、メタデータ）はすべて英語で記述すること。** ドキュメントは原則日本語とする。
*   **目的**: 複雑なロジックについては、*何をしているか* ではなく、*なぜそれをするのか* を記述すること。
*   **契約 (Contracts)**: インターフェース定義のコメントには、自然言語（英語）で契約（事前/事後条件）を記述すること。

## 7. モダンC++とベストプラクティス

*   **静的確定**: `constexpr`, `consteval`, `static_assert` を積極的に使用し、可能な限りコンパイル時に検証を完了させる。
*   **所有権管理**: `std::unique_ptr` や `std::shared_ptr` は使用しない。
*   **RAII**: 全てのリソース解放をデストラクタに任せる。手動の `free` / `unlock` 呼び出しは禁止。
*   **`void*` の禁止**: 型安全性を確保するため、`void*` の使用は禁止する。`binary_view` や `std::span<std::byte>` を使用すること。

## 8. 禁止されるコンテナとテクニック

*   動的メモリ確保を伴うコンテナ（`std::vector`, `std::map`, `std::string` 等）は原則禁止。
*   代替として [Resource Optimization](../skills/cpp_embedded/SKILL.md) を参照すること。

## 9. インターフェース定義のワークフロー

1.  **オブジェクト指向設計**: オブジェクト指向プログラミングの原則を用いてインターフェースを設計する。
2.  **命名**: 設計レベルの名称を使用し、実装詳細は隠蔽する。
3.  **定義**: [構造設計パターン](/docs/patterns/structural_patterns.md) に従い、ヘッダファイルにインターフェースを定義する。
4.  **契約**: コメントに自然言語（英語）で契約を記述する。

| **禁止事項** | **禁止** | `using namespace std;` の使用 |

| **モダンC++** | **示唆** | マクロの代わりに `constexpr` 定数を使用できないか |
