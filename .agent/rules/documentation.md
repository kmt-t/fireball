# ドキュメント作成と品質のルール

## ドキュメントの生成ルール

ドキュメントを書く際には下記のルールに従う。

1. 既存の仕様を削除してはならない。重複を削除したり、仕様を別の表現にしてもいいが、論理的に同じ内容であること。
2. 仕様の欠落を発見した場合は、勝手に補完せずバックログに記録するかユーザに質問する。
3. 章・節・項は構造化した構成とすること。
4. ドキュメントは原則日本語で記述する。
5. 図のテキストは英語で記述する。
6. ドキュメントの設計ができたらタスクを終了する
7. 設計とコードの生成は必ず別タスクとする。
8. 章・節の頭に全体的な概略を完結に書く。
9. 簡潔に書き、意味的に重複がある冗長な表現は避ける。
10. サンプルコードはC++の処理を概念的にPythonで記述する。
11. 図はMermaid記法で記述する。

## ドキュメント品質基準

### 基本原則
- **Contract-First**: 外部仕様は振る舞いの契約として記述し、実装詳細（データ型など）への依存を排除する。
- **Traceability**: 全ての設計判断は要求キーワード `{Keyword}` から導出され、逆向きの追跡が可能であること。
- **Strict Logic**: 曖昧な自然言語を避け、状態、条件、副作用を明確に分離して記述する。
