# 全体設計ルール

本ドキュメントは、プロジェクトの核となる哲学、アーキテクチャ原則、およびドキュメント標準を定義する。これらのルールは言語に依存せず、すべての設計判断の基盤となる。

## 1. 中核哲学

*   **盆栽デザイン**: 「盆栽」のように反復的なアプローチをとる。全体と詳細を行き来し、少しずつ調整する。課題が発生した場合は、立ち止まらずにバックログに送り、次の反復で解決する。
*   **厳密なロジック**: 曖昧な自然言語を避ける。状態、条件、副作用を明確に分離して記述する。
*   **トレーサビリティ**: すべての設計判断は、要求キーワード `{Keyword}` まで追跡可能でなければならない。
*   **再現性**: ソースコード生成 シェルスクリプトや設定ファイルを含む は再現性がなければならない。

## 2. アーキテクチャと方法論

*   **設計駆動**: 設計が最優先である。実装は設計の派生物に過ぎない。明確な設計なしにコードを書いてはならない。
*   **契約優先**: 実装する前に、外部仕様を契約 振る舞いの保証 として定義する。仕様が実装詳細に依存しないようにする。
*   **WIT-First**: **WIT IDL** はシステムインターフェースの唯一の **真実在** である。すべてのコンポーネントインターフェースとクラスは WIT 定義から始まる。
    *   **導出**: C++ ヘッダは WIT から自動生成される。
*   **ATC**: 複雑なタスクを開始する際は、認知ドリフトを防ぎ論理的制約を強制するために、ATC `@pre`, `@inv`, `@post` を定義する。
*   **クリーンアーキテクチャ & IoC**:
    *   **制御の反転**: インターフェースは内側の層が定義する。
    *   **フラットなインターフェース**: コンポーネント境界をフラットに保つ。深い継承やネストされた抽象化を避ける。
    *   **薄いグルー**: コンポーネント間のグルーコードを最小限にする。

## 3. ドキュメント標準

*   **言語**:
    *   **ドキュメント**: 原則として **日本語**。
    *   **図**: テキストは **英語**。
    *   **ソースコード (コメント/ログ)**: **英語のみ**。
*   **構造**:
    *   **契約**: インターフェースヘッダには、自然言語 英語 で契約 事前・事後条件 を記述する。
    *   **目的**: *何をしているか* だけでなく、*なぜそうするのか* を説明する。
    *   **トレーサビリティ**: キーワードのトレーサビリティマトリクスを維持する。未解決事項を確認する。
*   **書式規約**:
    *   **括弧の排除**: 補足、英語併記、例示などを `( )` や `（ ）` で囲まない。括弧を使わず「用語 英語」「用語 補足」のように記述せよ。
    *   **不要な英語の排除**: 日本語で十分伝わる箇所、または自明な箇所に英語表記を付け加えない。情報の密度を最大化し、視覚的ノイズを最小化せよ。
*   **品質ルール**:
    1.  既存の仕様を削除しない。論理的に等価な場合のみリファクタリングまたは統合を行う。
    2.  欠落している仕様を黙って埋めない。ユーザーに確認するか、バックログに問い合わせる。
    3.  すべての図には Mermaid を使用する。
    4.  ドキュメント内のサンプルコードは、複雑な C++ ではなく Python 擬似コードを使用する。
