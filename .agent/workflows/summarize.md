# サマライズのワークフロー

※ サマライズしたドキュメントは `docs/gen/summary.md` に保存すること。

ユーザが「サマライズしよう」と言ったらサマライズモードに入ること。

設計するときに散らばったドキュメントを全部読まなくてもよいようにするために下記のフォルダの内容をサマライズする。

- `docs/orders/patterns/*.md`
  - 設計パターンを4000文字程度にまとめる。
- `docs/orders/components/*.md` `docs/orders/concept/*.md`
  - コンポーネントの依存関係の図を入れる。
  - コンポーネントの設計で使っているテクニックの概念、狙っている効果、解決する問題を6000文字程度にまとめる。
  - コンポーネントの設計意図、設計を12000文字程度にまとめる。

解像度が高く情報密度の高い記述とすること。表現として難解でもかまわない。また元のドキュメントへのリンクを添付すること。

サマライズの目的は設計の際にすべてのファイルを探す手間を省くためであるため、設計のホールネス、インテグリティを保つために必要な情報を漏れなく記載すること。
