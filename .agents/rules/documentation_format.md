name: documentation-format-standards
globs: ["docs/**"]
scope: LOCAL
instructions: |
  1. 図表の表記規約: すべてのドキュメント内の図（ブロック定義図、シーケンス図、状態遷移図など）は Mermaid 記法で記述する。Markdown コードブロック内に埋め込み、`mermaid` 言語指定で囲むこと。
  2. 検証コードの言語: 形式検証モデル（TLA+）、動作検証、シミュレーションのコードは Python で実装する。TLA+ は検証仕様定義のための DSL であり、実行・検証ロジック自体は Python で記述。
  3. 自動検証スクリプト: Keyword 検証、Tier 規制チェック、フリクション検出などの自動検証ツールは shell 入口を用意し、`tools/` か `verify/` 配下に配置する。
  4. ドキュメント内の表形式: 複雑なデータ構造（API 定義、パラメータ一覧）は必ず表形式（Markdown テーブル）で記述。コードブロック形式は避けること。
  5. 言語混在の禁止: 同一ドキュメント内での表記ゆれを避けるため、以下を厳守すること。
     - 日本語: ドキュメント本文、設計説明、コンセプト
     - 英語: コード、API 名、キーワード `{Keyword}`, URI スキーム
     - 図: 英語のみ（Mermaid 内のラベルも英語）
  6. 参照リンク: コンポーネント設計間の参照はプロジェクトルートディレクトリからの相対パスで記述。
---
本ルールは、Fireballプロジェクトのドキュメント品質と一貫性を保証し、自動検証ツールとの連携を円滑にするための標準形式である。
