# スキルドキュメント フォーマット定義

本ドキュメントは、プロジェクト内の各スキル（`.agent/skills/*/SKILL.md`）の標準的な構成と記述内容を定義します。

## 1. 必須セクション構成

すべての `SKILL.md` は以下の構成に従わなければなりません。

### 1.1 YAML フロントマター
ファイルの冒頭に配置します。エージェントがスキルの関連性を判断するために重要です。

```yaml
---
name: スキル表示名
description: >
  概要を簡潔に記述。
  WHEN: 発動条件（どのような状況で使用するか）
  SCOPE: 適用範囲（対象となるファイルやレイヤー）
  RELATED: 関連する他のスキルやドキュメント
---
```

### 1.2 概要
- スキルが解決する問題。
- 使用することによる利点（認知負荷の低減、品質向上など）。
- アーキテクチャ上の位置付け VDD, IoC, Zero-cost DI等との関連。

### 1.3 環境・前提条件
- 必要なツール Docker, wasm-tools, Python, Meson等。
- 実行環境の制約（WindowsでのWSL2使用必須、コンテナ使用必須など）。
- 依存する他のスキル。

### 1.4 使用方法
ユーザーまたはエージェントが迷わずに実行できるよう、具象的なコマンド例を提示します。

- **統合実行 Integrated Runner**: `docker-generate-code.sh` 等、環境に依存しない推奨される実行方法。
- **個別実行 Granular Execution**: 特定のスクリプトやワークフローを直接実行する方法。
- **パイプ利用**: 汎用性を高めるための標準入力経由の実行例（もしあれば）。

### 1.5 構成要素の詳細
スキルに含まれる主要なスクリプトや設定ファイルの説明。
- **scripts/**: 各 Python/Shell スクリプトの役割。
- **workflows/**: 実装されているワークフローの意図。

### 1.6 品質・検証ルール
スキルが担保する品質基準や、チェック項目。
- 禁止パターンの検出対象。
- 命名規則のバリデーション内容。

### 1.7 トラブルシューティング
よく発生するエラーとその解決策。

## 2. 記述スタイルガイドライン

- **情報の密度**: 冗長な表現を避け、事実と論理を優先する。
- **絶対パスの回避**: 特定の PC 環境に依存する絶対パスを禁止し、プロジェクトルートからの相対パス（`.agent/...` 等）を原則とする。
- **リンク**: 関連ファイルには `[basename](.agent/relative/path)` 形式でプロジェクトルート リポジトリルート からの相対パスでリンクを張ること。
- **英語と日本語の使い分け**: [全体設計ルール](.agent/rules/general_design_rule.md) に従い、本文は日本語、技術用語や図は英語を基本とする。
