# 最上位アーキテクチャ監査ルーブリック (Architecture Review Rubric)
本ルーブリックは、最上位アーキテクチャ設計書（`docs/architecture/architecture_overview.md`）を構造の地図として評価する。個別コンポーネントのアルゴリズム、ABI、形式検証、テスト、リソース見積もりは評価対象に含めず、それらを概要書へ重複記載していないかだけを確認する。

## 1. 評価軸

### 1.1 Tier 分類

| 判定 | 基準 |
| :--- | :--- |
| 適合 | すべてのコンポーネントが正しい Tier のディレクトリと一覧に対応する。契約と具体実装の階層も逆転していない。 |
| 不適合 | Tier の取り違え、旧 Tier 名の残存、契約と実装の逆転、または分類根拠のない移動がある。 |

確認項目:

- Tier 表と docs/components/ のディレクトリが一致する。
- tier3_executer は Interpreter と JIT、tier3_plugins は Debugger と Guest Profiler を含む。
- tier3_platform は物理ドライバとゲスト側アダプタを含む。
- Tier 2 はランタイムのライフサイクルとプラグイン・観測契約を定義し、Tier 3 の具体実装を所有しない。

### 1.2 責務境界

| 判定 | 基準 |
| :--- | :--- |
| 適合 | 各コンポーネントの責務を一文で区別でき、同一責務の所有者が一つである。 |
| 不適合 | 複数コンポーネントが同じ責務を所有する、または概要書と詳細書が同じ仕様を正本として主張する。 |

確認項目:

- コンポーネントごとに責務の主語と対象が明確である。
- Runtime の契約、Executer の実行、Plugins の交換可能な実装、Platform の物理接続が混在していない。
- 概要書は分類に必要な一文とリンクだけを持ち、詳細仕様を再掲していない。
- 同じ責務を別名のコンポーネントへ分割していない。

### 1.3 依存関係

| 判定 | 基準 |
| :--- | :--- |
| 適合 | 依存元から依存先への矢印が一貫し、契約から実装への方向が守られる。循環や逆流がない。 |
| 不適合 | Tier の下位から上位の具体実装へ依存する、循環依存がある、または図と文書の依存関係が異なる。 |

確認項目:

- Tier 3 は Tier 2 の契約を利用し、Tier 2 は Tier 1 の契約を利用する。
- 上位 Tier が下位 Tier の内部構造に依存しない。
- プラグインが Runtime の契約を利用し、Runtime がプラグインの具象型へ依存しない。
- 図のすべてのノードが依存関係上の意味を持つ。
- 循環、逆方向矢印、同一責務を跨ぐ不要な依存がない。

### 1.4 一覧とリンク

| 判定 | 基準 |
| :--- | :--- |
| 適合 | Tier 表、図、一覧、リンク先ファイルが同じコンポーネント集合を表す。 |
| 不適合 | 欠落、重複、リンク切れ、旧ファイル名、または図と一覧の不一致がある。 |

確認項目:

- Mermaid のノード名とコンポーネント一覧の名前が対応する。
- 一覧のリンク先が存在する。
- 一覧にないコンポーネントが図に存在しない。
- 新旧 Tier のパスが混在していない。
- リンクの相対パスがこの文書の位置から解決できる。

## 2. 重大度

- CRITICAL: Tier の逆転、契約境界の逆流、依存循環など、アーキテクチャの成立を壊す不整合。
- MAJOR: 責務重複、コンポーネントの欠落、リンク切れ、図・一覧・実ファイルの不一致、概要書への詳細仕様の再掲。
- MINOR: 表現の曖昧さ、責務説明の不足、命名やリンク表記の軽微な不整合。

## 3. 判定方法

1. collect_arch_context.py --json で Tier 別ファイル、図のノード、リンク先を収集する。
2. 4つの評価軸を個別に確認し、問題のファイルと行を記録する。
3. 同じ原因から生じた指摘は一つの設計問題としてまとめる。
4. CRITICAL または MAJOR がなければ PASS、MINOR のみなら WARN、CRITICAL または MAJOR があれば FAIL とする。
5. 修正後は一覧、図、リンク、および依存方向を再確認する。

## 4. 対象外

次の内容は本レビューの判定軸にしない。

- JIT の検索方式、キャッシュ方式、コード生成アルゴリズム。
- Interpreter の命令実装やスタック構造。
- ABI のバイト配置、物理レジスタ、メモリレイアウト。
- IPC、vMMIO、WASI、形式検証モデルの個別不変条件。
- C++、Python、概念コード、テストコードの実装品質。

これらは各コンポーネントの仕様・検証レビューで扱い、architecture_overview.md には詳細を戻さない。
