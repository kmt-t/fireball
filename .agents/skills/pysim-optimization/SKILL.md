# pysim 計測・最適化

## 目的

experiments/pysim の代表ワークロードを Intel VTune Profiler または AMD uProf で測定し、実測根拠のある最適化案をターゲットの資源制約と設計境界に沿って評価する。通常のソースコードレビューには [pysim-review](../pysim-review/SKILL.md) を使う。

## 対象

対象は指定された処理、代表ワークロード、関連ベンチマーク、コンポーネント仕様である。コード変更はユーザーが実装も依頼した場合に限る。

## 手順

1. **ワークロードを定める**: 入力、実行条件、意味的に正しい結果を決める。既存ベンチマークと統合シナリオで計測範囲を確認する。
2. **設計と予算を読む**: Python規約、システムコンテナ・設定、対象Tier仕様、資源予算の正本を確認する。資料間の数値が不一致なら余剰予算を仮定しない。
3. **計測器を選ぶ**: ユーザー指定を優先する。指定がなければ、インストール済み VTune または AMD uProf のうち対象OS、CPU、Python版、分析目的に対応するものを選ぶ。利用可能な版、CLIヘルプ、公式ガイドを確認し、対応しない分析を推測で代用しない。
4. **基準を測る**: 同一環境・同一入力で複数回計測し、ばらつき、計測オーバーヘッド、結果の正当性を確認する。対象関数のCPUホットスポット、割当て、ハードウェアイベントは、選んだ計測器が実際に対応する範囲だけ読む。
5. **候補を順位付けする**: [最適化判断フレームワーク](references/optimization-decision-framework.md)で速度、ROM/RAM、最悪時時間、設計・Tier境界を比較する。ホスト上のPython計測をMCU上のC++性能や物理資源量と同一視しない。
6. **提案または実装を完了する**: 提案だけなら変更案と検証方法を報告する。実装依頼がある場合は仕様・所有権・Tier依存を保ち、関連するテストと同条件ベンチマークで振る舞いと差分を確かめる。

## チェックリスト

- 計測前後でワークロード、入力、正当性条件が同じである。
- CPU時間、Python割当て、ハードウェアイベントの各結果を、計測器と実行環境の対応範囲内で解釈する。
- 基準測定の回数、ばらつき、計測オーバーヘッドを記録し、ノイズ以下の差を改善と呼ばない。
- 各案にROM/RAM、容量、初期化、最悪時時間、複雑さ、Tier境界のコストを含める。
- 測定値、静的見積もり、仮説、未確認事項を区別する。
- 生のプロファイル結果は依頼がない限り一時領域に置く。

## 結果

案を優先度順に提示し、計測根拠、期待効果、資源コスト、採否、検証方法を記す。根拠が足りない案は採用を推奨せず、未確認事項として示す。[共通レビュー手順](../review-protocol.md) の証拠・所見形式も適用する。
