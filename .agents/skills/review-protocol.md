# 共通レビュー手順

この文書は、architecture-review、component-review、pysim-review の証拠確認と報告形式、および pysim-optimization の証拠記録をそろえる。各スキル固有の判定項目は、それぞれが指定するルーブリックを正本とする。

## 手順

1. **範囲を決める**: 指定対象と変更範囲を特定し、上位の仕様、適用ルール、直接関係する実装・検証資料を確認する。
2. **証拠を集める**: 付属スクリプトがあれば実行し、結果を実ファイルと照合する。スクリプト出力だけで適合を判定しない。
3. **チェックする**: スキル固有チェックリストの全項目を確認し、非該当項目は理由を記録する。矛盾や欠落は該当する正本まで追跡する。
4. **所見をまとめる**: 同じ原因の指摘を統合し、観測事実、影響、推奨対応を分ける。推測や未確認事項は事実として書かない。
5. **完了を判定する**: すべての適用項目に判定があり、所見ごとに再確認できる証拠が示されていることを確認する。

## 重大度と判定

- **CRITICAL**: 安全性、正しさ、契約、依存境界を壊す重大な違反。
- **MAJOR**: 必須要件、設計整合性、検証可能性を損なう問題。
- **MINOR**: 理解や保守性を下げるが、必須要件を破らない問題。

レビュー結果は CRITICAL または MAJOR があれば `FAIL`、MINOR のみなら `WARN`、指摘がなければ `PASS` とする。最適化調査ではこの判定を使わず、候補ごとの採否と優先度を示す。

## 所見の形式

各所見は次の情報を含める。

```text
[重大度] 要約 — path/to/file:line
証拠: 該当する記述・動作と確認方法
影響: 要件または設計への具体的な影響
対応案: 直す場所と方向
```

レビュー結果には、総合判定、重大度別件数、適用したチェック項目、実行した検証と未確認事項を添える。最適化調査は、計測条件、候補順位、資源見積り、未測定項目を記録する。修正依頼のないレビューや最適化調査では、対象成果物を変更せず所見・案を返す。
