# アクションプラン (2026/01/22 進捗会議結果)

進捗会議での分析に基づき、設計フェーズ（Phase 0）の完了と実装フェーズ（Phase 1）への円滑な移行のためのアクションプランを優先度順に記述する。

## 優先度 1: vSoC 開発のアンブロック (最優先)

vSoCの先行開発を可能にするため、必要最小限の周辺インターフェースを確定させる。

- [ ] **周辺コンポーネントの最小インターフェース定義**:
    - `router` (IPC): URIベースの名前解決とチャネル取得のAPI定義。
    - `hal`: vSoCが必要とする最小限のデバイス抽象化（UART, Timer等）の定義。
    - `coos`: タスクスイッチおよび割り込みウェイクアップのインターフェース定義。

## 優先度 2: vSoC 詳細設計へのリソース集中

プロジェクトの核となる vSoC の設計密度を上げ、WAMRに対する優位性を確実にする。

- [ ] **vSoC インターフェース定義**: `inc/vsoc.hxx` 等への具体的なC++インターフェース定義。
- [ ] **JIT詳細設計**: Copy-and-Patch方式のテンプレート生成およびパッチ適用の詳細アルゴリズム策定。
- [ ] **メモリモデルの精緻化**: ゲストヒープとホスト側の境界、およびスタック管理の詳細設計。

## 優先度 3: トレーサビリティと一貫性の確保

設計の品質を担保し、手戻りを防ぐ。

- [ ] **トレーサビリティマトリクスの作成**: `docs/gen/trace/` 配下での要求事項と設計の紐付け確認。
- [ ] **表記揺れチェック**: 全ドキュメントを通じたキーワード・用語の統一。

## 優先度 4: 周辺コンポーネントの精緻化

vSoCの動作を支える周辺機能の設計を完了させる。

- [ ] **デバッガ (RSP) 仕様の最小化**: 15 KLOC制限を遵守するための機能絞り込み。
- [ ] **ロギング・診断機能の設計**: 実行時オーバーヘッドを最小化するロギング機構の策定。

## 優先度 5: ベンチマーク環境の構築

- [ ] **vSoC スタンドアロン・ハーネスの作成**: Linux上での評価環境構築。
- [ ] **WAMR比較評価の実施**: CoreMark-PRO等を用いた性能・メモリ消費の定量的評価。
