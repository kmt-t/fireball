# アクションプラン

最終更新: 2026/01/21（ワイガヤ結果反映）

## スケジュール調整（2026/01/21 合意）

**Phase0を1ヶ月延長、Phase1を1ヶ月縮小:**
- Phase0: ～2026/02末 → ～2026/03末（+1ヶ月）
- Phase1: 4ヶ月 → 3ヶ月（-1ヶ月）
- **総期間は変更なし**: 年内リリース目標を維持

**調整の理由:**
- vSoCの設計を完璧に固めることを最優先
- 周辺コンポーネントは最小インターフェース定義でOK
- Phase1での手戻りを防ぎ、実装効率を最大化

## 優先度 1: vSoC設計の完璧な完成（最優先）

Phase0延長により、vSoCの設計を完璧に固めることに集中する。

- [ ] **vSoC詳細設計の完成**:
    - インタープリタ実行モデルの完全な定義
    - JITテンプレート設計（constexprアセンブラ仕様含む）
    - メモリモデル（ゲスト/ホスト境界、スタック管理）の精緻化
    - 実行コンテキスト構造体の完全定義
    - vMMIOレジスタマップの確定

- [ ] **vSoC C++インターフェースの完全定義**:
    - `inc/vsoc.hxx` の完成
    - 全パブリックAPIのシグネチャ確定
    - エラーハンドリング体系の明確化
    - ライフサイクル管理の詳細設計

- [ ] **JIT実現可能性の検証**:
    - constexprアセンブラの技術的PoC（1-2日）
    - ARM/RISC-V両対応の難易度確認
    - テンプレート生成の行数見積もり
    - Copy-and-Patchパッチ処理の詳細設計

## 優先度 2: 周辺コンポーネントの最小インターフェース定義（ほどほどでOK）

vSoCの先行開発を可能にするため、Mock実装可能なレベルのインターフェースを定義する。

- [ ] **COOS最小インターフェース**:
    - `co_yield`, `co_await` の型定義
    - タスク起動・停止のAPI定義
    - Mock実装可能なレベルで十分

- [ ] **IPC Router最小インターフェース**:
    - URI解決APIの定義
    - チャネル取得のAPI定義
    - Mock実装可能なレベルで十分

- [ ] **HAL最小インターフェース**:
    - vSoCが必要とする最小限のデバイス抽象化
    - UART, Timerのstub定義
    - Mock実装可能なレベルで十分

## 優先度 3: トレーサビリティと一貫性の確保

設計の品質を担保し、手戻りを防ぐ。

- [ ] **トレーサビリティマトリクスの作成**: `docs/gen/trace/` 配下での要求事項と設計の紐付け確認。
- [ ] **表記揺れチェック**: 全ドキュメントを通じたキーワード・用語の統一。

## 優先度 4: 周辺コンポーネントの精緻化

vSoCの動作を支える周辺機能の設計を完了させる。

- [ ] **デバッガ (RSP) 仕様の最小化**: 15 KLOC制限を遵守するための機能絞り込み。
- [ ] **ロギング・診断機能の設計**: 実行時オーバーヘッドを最小化するロギング機構の策定。

## 優先度 5: Phase1準備

Phase0完了後、速やかにPhase1に移行できるよう準備する。

- [ ] **vSoC スタンドアロン・ハーネスの設計**: Linux上での評価環境の設計。
- [ ] **WAMR比較ベンチマーク計画の詳細化**: 評価項目と手順の明確化。
- [ ] **Phase1タスク分解**: 3ヶ月での実装完了に向けた詳細計画。
