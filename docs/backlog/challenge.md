# 設計の交差点 (Challenges)

Fireballの開発において、複数の制約や要件が衝突し、慎重なトレードオフ検討が必要な設計項目を管理する。
エージェント向けの構造化インデックスは `.agent/brain/backlog.atc` を参照。

## 1. WASI `fd_write` (scatter-gather) の実装レイヤー分離 `{Challenge_WasiFdWriteLoop}`

### 概要
WASIの `fd_write` は `ciovec` 配列を受け取るが、このループ処理をどこで行うか。

### 交差点
- **ホストのシンプルさ**: ホスト側で `iovs` をパースすると、境界チェックやループ処理のコードが増える（15KLOC制限への影響）。
- **実行パフォーマンス**: ゲスト側（Shim）でループを回すと、`fireball_call` (トラップ) の回数が増え、オーバーヘッドが増大する。

### 現在の方針 (2026-01-25)
- **検討中**: 原則としてホストを小さく保つため「Shim側でループ」を優先検討するが、ベンチマーク結果次第でホスト側一括処理への切り替えを検討する。

## 2. vMMIO システムコールにおけるメモリ安全性の確保 `{Challenge_SyscallMemorySafety}`

### 概要
ゲストが vMMIO レジスタに書き込んだ「ポインタ」をホストが参照する際の安全性。

### 交差点
- **安全性**: ゲストが悪意のある（またはバグのある）ポインタを渡した場合、ホストがクラッシュしたり、ホストメモリを破壊したりするリスクがある。
- **パフォーマンス**: 毎回厳密な境界チェック（`guest_addr + size <= ram_size`）を行うコスト。

### 解決済み — 統一vMMIOモデルに吸収 (2026-02-17)
- vMMIO許可テーブルが唯一のセキュリティゲートとなり、すべてのホスト-ゲスト間データ交換（GPIO、共有メモリバッファ、syscall引数）が同一のパスを通る。
- `vsoc_validate_ptr` は別メカニズムではなく、vMMIO許可テーブルチェックそのものである。
- 許可されたアドレスへのアクセスはノーチェック（ゼロコスト）で直接物理アクセス。
- @see `docs/components/vmmio.md` §1, §4

## 3. COOS `BLOCKED` タスクリストの管理コスト `{Challenge_CoosBlockedList}`

### 概要
スケジューリング効率化のため、`READY` キューとは別に `BLOCKED` 状態のタスクをリストで管理する。

### 交差点
- **スケジューリング性能**: `READY` タスクのみを走査することで、アイドルループの無駄を排除できる。
- **メモリ・複雑性**: `task_t` にリストポインタを追加する必要があり、RAM 64KB制約下では無視できない。また、状態遷移（`READY` ↔ `BLOCKED`）時のリスト操作がアトミックである必要がある（特にISRからのウェイクアップ時）。

### 現在の方針 (2026-01-25)
- `task_t` に `next_blocked` ポインタを追加し、単方向リストで管理する。
- ISRからのウェイクアップ時は、直接リスト操作をせず、`INTERRUPTED` フラグを立てて次回のスケジューラ実行時にリストから戻す方式を検討する。

## 4. CSP Handoff (Direct Switch) によるスターベーション `{Challenge_CspHandoffStarvation}`

### 概要
CSP通信において、送信側が受信待ちタスクを発見した際に即座にコンテキストスイッチする最適化（Handoff）を導入する。

### 交差点
- **レイテンシ**: 通信のオーバーヘッドが劇的に減少し、要求-応答パターンの性能が向上する。
- **公平性（Fairness）**: 2つのタスクが頻繁に通信し合う場合、他の `READY` 状態のタスクに実行権が回らなくなる可能性がある。

### 決定済み方針 (2026-02-17)
- Handoffを導入する。
- **Formal Verification**: `ipc_handoff.tla` において、送信側から受信待機タスクへの「直接スイッチ（Handoff）」ロジックを形式モデル化し、メッセージ所有権の整合性とデッドロックの不在を検証済み。
- スターベーション対策として `{Challenge_ApproximateYield}` (トレース数ベースの強制Yield) を予定通り併用する。
