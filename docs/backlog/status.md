# バックログ対応状況ステータス

更新日: 2026-01-19

## 1. 最優先課題: RAM最適化戦略 (Success Criteria 達成のため)

| ID | 課題内容 | 優先度 | ステータス | 備考 |
|:---|:---|:---|:---|:---|
| R1 | WAMR比 RAM < 10KB の達成 | 最高 | **検討中** | JITキャッシュ(2KB)を含む全コンポーネントのRAM精査が必要 |
| R2 | JITダブルバッファのメモリ効率化 | 高 | **未対応** | Active/Old遷移時の断片化防止と再利用性の検討 |
| R3 | 静的解決によるRAM節約の極大化 | 高 | **未対応** | 実行時メタデータをROMへ追い出す設計の徹底 |

## 2. 仕様レビュー指摘事項

| ID | 指摘事項 | 優先度 | ステータス | 備考 |
|:---|:---|:---|:---|:---|
| 1 | loader.md: インターフェイス定義の不完全性 | 高 | **未対応** | 関数シグネチャ（`load`, `unload`等）の定義が必要 |
| 4 | vsoc.md: インタープリタの継続渡し実装の詳細不足 | 高 | **未対応** | `InstructionHandler` 等の型定義が必要 |
| 6 | vsoc.md: ランタイムAPI の関数型が未定義 | 高 | **未対応** | `RuntimeAPIFunction` 等の型定義が必要 |

## 3. 次のアクション

1. **RAMバジェットの策定**: 各コンポーネント（COOS, vSoC, IPC Router）に割り当てるRAMの「上限値」を厳格に定義する。
2. **コンポーネント詳細設計**: `docs/gen/components/` において、RAM消費を最小化するインターフェイスとデータ構造を定義する。
3. **JITキャッシュの具体化**: ダブルバッファ方式におけるコピー/再コンパイルのトリガー条件を詳細化する。
