# エージェント用セルフチェックリスト

このドキュメントは、エージェントがコンポーネントの仕様書（`docs/components/*/*.md`）を作成または修正した際に、ドキュメントの整合性を自律的に確認するためのセルフチェックリストである。機械的なスクリプトによる判定ではなく、コンテキストを考慮したエージェント自身の推論による検証を目的とする。仕様の修正やリファクタリングの最後には、必ずこのリストに照らし合わせてドキュメントをセルフレビューすること。

## 1. WIT（真実在）との完全な一致
- [ ] **API・インターフェース名の同期**: ドキュメント内の「公開API」メソッド名、および説明文中の関数呼び出し名は、最新のWIT IDLの定義と完全に一致しているか（古い名称が残っていないか）。
- [ ] **引数・戻り値の同期**: テーブルに記載された引数や戻り値の役割が、WIT定義のシグネチャと矛盾していないか。
- [ ] **事前/事後/不変条件 (ATC)**: WIT側で意図されているロジック（`@pre`, `@post`, `@inv`）が、ドキュメント側の契約（事前条件、事後条件、不変条件）と論理的に合致しているか。
- [ ] **ATCの推論と抽出**: APIの引数や状態遷移から、見落とされがちな新しいATC（`@pre`, `@post`, `@inv`）を抽出する際、以下の順序でプロセスを踏んでいるか。
    - **ドメイン知識の積極的な確認 (最優先)**: システム全体の仕様や「暗黙の前提」は人間のユーザーしか知り得ない場合が多いことを認識し、エージェント自身の憶測で補完する前に、まずユーザーに対して積極的に「この変数には◯◯という前提（事前条件）があるか？」と質問して仕様の方向性を確定させているか。
    - **定数の限界値/無効値からの導出**: ヘッダやドキュメント内で定義されている定数（最大数、特殊な初期値など）が、関数呼び出し時の暗黙の事前条件（あるいは事後条件、不変条件）となっていないか。
    - **他コンポーネントからの制約波及**: 呼び出し先、あるいは呼び出し元のコンポーネントが持つ制約（例: メモリ制限、排他制御の状態）が、このAPIの契約として明文化されるべきではないか。

## 2. 図解（Mermaid）の整合性
- [ ] **図と最新APIの不一致排除**: シーケンス図、状態遷移図、ブロック図のなかのメッセージ名・関数名に、古いAPI名が残っていないか（WITと同期されているか）。
- [ ] **英語表記の徹底**: Mermaid図の内部テキストは、原則としてすべて**英語**で記述されているか（日本語が混入していないか）。
- [ ] **図の役割**: 静的モデル（ブロック図）と動的モデル（シーケンス図・状態遷移図）が適切にセットで存在し、それぞれが矛盾していないか。

## 3. フォーマットと記述規約の遵守（全体設計ルール）
- [ ] **インターフェースのテーブル記述**: 構造体やAPIの定義は、実装言語のコードブロックを使わず、`FORMAT.md`に従い必ず表（テーブル）形式で記述されているか。
- [ ] **自然言語による項目名**: テーブルの項目名欄は、変数名そのままではなく、その意味を表す**自然言語（日本語）**になっているか。
- [ ] **括弧の徹底排除**: 補足、英語併記、例示などを `( )` や `（ ）` で囲んでいないか（正：「用語 英語」、誤：「用語 (英語)」）。
- [ ] **不要な英語の排除**: 日本語で十分伝わる自明な箇所に英語表記を付け加え、情報のノイズにしていないか。

## 4. 全体設計とトレーサビリティの適用
- [ ] **TODOマーキングの適用と強制前進**: 仕様が即座に決まらない未決定事項について、そこで立ち止まったりエージェント自身の憶測で埋めたりせず、`.agent/rules/project_protocol_rule.md` に従い `TODO(Phase X): [課題] - [アクション]` の形式で明示的にマーキングし、強制的に次の設計ステップへ進んでいるか。
- [ ] **トレーサビリティの確保**: 設計判断や制約の理由となる上位要求キーワード `{Keyword}` が、適切なセクションに見失われることなく記述されているか。
- [ ] **厳密なロジック**: 状態、条件、副作用が明確に分離されているか。曖昧な自然言語でごまかしていないか。
- [ ] **欠落した仕様の補完禁止**: 既存の仕様を勝手に削除したり、明確な指示がないのに欠落している仕様を黙って独自に埋めたりしていないか（不明点は確認またはバックログへ）。

### レビュー実施時のプロンプト（例）
エージェントへの指示の最後に以下を付与して実行させる。
`"最後に、docs/components/CHECKLIST.md を読み込み、修正したドキュメントがリストのすべての項目を満たしているかセルフチェックし、問題があれば修正してください。"`
