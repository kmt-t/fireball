# コンポーネント設計フォーマット

このフォーマットは、`docs/components/tier*/` 直下に置くコンポーネント設計書へ適用する。設計書は、責務、静的構造、動的振る舞い、インターフェース、制約、および検証証跡を定義する。コンポーネント設計書は、対応する要求仕様、WIT契約、形式検証モデル、コンセプトコード、テスト仕様書を参照して4層の設計チェーンを構成する。

トップレベルセクションは次の順序で記述する。各セクション内の詳細見出しはコンポーネントの責務に合わせて追加する。契約のみの文書やWIT・ゲストアダプタ文書は、該当しない静的・動的詳細を「対象外」と明記し、別の文書へ責務を移さない。

## 1. コンセプト

コンポーネントの目的、責務、責務境界、および設計上の主要な不変条件を記述する。対応する要求キーワードと、参照する上位契約を示す。

## 2. アーキテクチャ分類

コンポーネントのTier、配置理由、依存方向、契約または実装としての位置づけを記述する。上位Tierの契約と下位Tierの具象実装を混在させない。

| 項目 | 内容 |
| :--- | :--- |
| Tier | 所属するTierとディレクトリ |
| 役割 | 契約、Runtime統合、実行系、プラグイン、Platform具象のいずれか |
| 依存先 | 参照する上位契約または同一Tierの公開契約 |
| 被依存側 | この文書を参照するコンポーネント |
| 正本 | 対応するWIT、要求、形式検証、テスト仕様のリンク |

## 3. 静的モデル

内部構造、データ構造、メモリ領域、主要な型の役割、および静的な依存関係を記述する。

### 3.1 データ構造

主要なデータ構造と選択理由を記述する。容量、所有権、可変性、およびROM・RAM配置の制約を明記する。

### 3.2 内部ブロック図

内部モジュールの関係をMermaidの`graph TD`で記述する。ノード名と本文の責務名を一致させる。

### 3.3 主要な構成要素

クラス、構造体、配列、定数、およびメモリ領域を表形式で記述する。項目名は自然言語で記述し、識別子は補足として括弧内に示す。

| 項目 | 機能と役割 | 制約・型・配置 |
| :--- | :--- | :--- |
| 構成要素名 | 役割と保持する情報 | 容量、所有権、型、ROM・RAM |

コードブロックによるC++実装定義を記載しない。擬似コードが必要な場合はPythonで記述する。

## 4. 動的モデル

コンポーネントの処理手順、状態、イベント、所有権遷移、および他コンポーネントとの相互作用を記述する。

### 4.1 アルゴリズム

主要な処理手順を記述する。条件分岐や検証手順が中心の場合は`flowchart TD`を使用する。

### 4.2 状態遷移図

状態と遷移条件をMermaidの`stateDiagram-v2`で記述する。契約だけで状態を持たない場合は、対象外の理由と契約上の不変条件を記述する。

### 4.3 内部シーケンス

コンポーネント間の責務委譲、メッセージ送受信、割り込み、ホストコール、またはリソース所有権の遷移をMermaidの`sequenceDiagram`で記述する。

## 5. インターフェース定義

外部へ公開するAPI、URI、IPC、WIT、host-call、イベント、およびエラー契約を記述する。シグネチャと型の正本がWITにある場合はWITへリンクし、Markdownへ重複定義しない。

### 5.1 公開API

APIの目的、引数の意味、事前条件、事後条件、不変条件、結果、およびエラー時の挙動を表形式で記述する。

### 5.2 URI・IPC・WITインターフェース

URI、メッセージ、WIT、host-call、イベントの公開方向と依存先を記述する。ビット配置やABIの正本は対応する外部仕様へリンクする。

## 6. 制約達成の方策

要求仕様の性能、メモリ、安全性、決定性、および実装規模の制約を記述する。

### 6.1 性能制約と方策

測定可能な目標値、適用するホットパス、計測方法、および未検証条件を記述する。

### 6.2 メモリ制約と方策

RAM・ROM予算、固定容量、所有権、アロケータ、実行時割り当て、およびW^X制約を記述する。

### 6.3 安全性・決定性制約と方策

境界検査、権限検査、エラー処理、障害隔離、決定性、およびリカバリー方策を記述する。

## 7. 形式検証・テスト仕様との対応

不変条件、形式検証モデル、コンセプトコード、テスト仕様書、および実行テストの対応を記述する。

### 7.1 検証対象の不変条件

安全性、活性、所有権、境界、状態遷移、およびエラー処理の不変条件を列挙する。

### 7.2 検証モデルと反証可能性

`pyModelChecking`のモデル、CTL・LTL特性式、`guards=False`変異検査、および既知の制限を記述する。実在する検証ファイルへリンクする。

### 7.3 テスト仕様書との連携

対応する `docs/qa/tier*/<component>_test_spec.md` または `docs/qa/specs/<spec>_test_spec.md` をリンクする。テストケースID、GOTCHA、直交表、および実行可能テストの対応を記述する。

### 7.4 既知の制限・対象外

未検証、対象外、実機依存、ベンチマーク依存、および別コンポーネントが正本となる範囲を明記する。

## 8. 設計判断と参考実装

重要なADR、トレードオフ、参考にしたOSS・標準仕様・論文、および採用理由を記述する。該当しない場合は「なし」と記載する。

設計書のタイトル直下には`<!-- evidence: ... -->`を置く。参照する形式検証、コンセプトコード、テスト仕様、WIT、およびベンチマークの実在パスを記載する。
