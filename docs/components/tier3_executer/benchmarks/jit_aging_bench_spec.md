# JIT カードエイジング ベンチマーク仕様書 (JIT Card Aging Benchmark Specification)

## 1. 目的と対象範囲
<!-- traceability: {JIT_CardAgingSweep} {JIT_MultiBuffer_Cache} {JIT_OldestOnly_Promote} {LowLatencyJIT} -->

正本: [`jit_runtime.md`](docs/components/tier3_executer/jit_runtime.md)（エイジングスイープ）
参考実装: [`bench_jit_aging.py`](experiments/pysim/benchmarks/jit/bench_jit_aging.py)

本ベンチマークは、エイジングスイープが不要なコンパイルと追い出しを抑えるかを測定する。
対象は、低頻度の関数が JIT キャッシュへ混入する状況である。

作業集合は2種類の関数で構成する。ホット関数は少数で、短いループを毎回実行する。そのトレース総量は3面キャッシュに収まる。コールド関数は多数で、少数ずつ順番に呼び出す。1つのコールド関数は、長い間隔を空けて実行される。

エイジングがない場合、コールド関数のカードは `EXECUTED` のまま残る。次の呼び出しで `HOT` になり、コンパイルされてホットトレースを追い出す。エイジングがある場合は、この間にカードが `UNEXECUTED` へ戻る。

## 3. 測定手順と判定基準

1. **基準の測定**:
   - コールド関数を呼ばず、ホット関数だけを実行する。
   - 追い出しが 0 件であることを確認する。この実行のコンパイル数は、ホット関数のトレース数を表す。
2. **汚染の測定**:
   - エイジングを止めた状態で、ホット関数とコールド関数を実行する。
   - ローテーションごとの処理だけを無効にし、ローテーション数は数える。
3. **エイジングの測定**:
   - U と O の組を変えて同じ実行を繰り返す。
   - 実行時間は参考値とし、合否には使わない。
4. **処理時間の測定**:
   - 各変種を3回実行し、時間の中央値を採る。
   - トレースコンパイラとエイジングの呼び出しを、それぞれ時計で囲んで累積する。
   - コンパイル数などの計数値は、3回の実行で一致することを確認する。
5. **判定**:
   - コンパイル数、追い出し数、ローテーション数は、決定的に再現する。
   - 実行時間と JIT 実行割合は、実行環境で変わる。JIT 実行割合は合否に使わない。

## 4. 未検証・スコープ外

- コールド関数の実行間隔と関数数の組み合わせは、1つの構成だけを定義する。
- エイジング1ステップの時間は、Python 実装の値である。C++ 実装の値を表さない。
- Cortex-M33 実機での、コンパイル時間とキャッシュ容量への影響は測定しない。
