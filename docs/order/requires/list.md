# 要件リスト

## 何をつくるのか

- wasm32ゲストを仮想化するハイパーバイザである。
- 小規模な組み込み向けである。

## 開発環境

- コンパイラ
  - clang
  - C99
  - C++23
  - libstdc++

## ターゲット

- ターゲットのMCUのアーキテクチャは下記のとおりである。
  - Cortex-M33
  - RISC-V/32
  - Linux
- 最小MCUターゲットはCortex-M33/RAM64KB/ROM128KBである。
- POSIX上で動くことは必須だが、その機能サブセットとして標準Cライブラリ、標準C++ライブラリ以外のライブラリは用いない。

# OS

- コルーチンを用いた協調型OSであるCOOSを独自設計する。
- FireballはRTOS（リアルタイムOS）ではない。厳密な時間制約や決定論的応答よりも、メモリ効率と移植性を最優先する。 `{NotRTOS}`
- シングルスレッド動作とし、グリーンスレッド（コルーチン）で並列処理を行う。 `{CooperativeMultitasking}`
- COOSの並列処理の同期はホーアCSPで行う。 `{CSPCommunication}`
- タスクの実行管理は公平性を期すためラウンドロビン方式とする。 `{TaskScheduling}`
- メモリ管理は独自のメモリ管理とする。 `{MemoryIsolation}`
- タスク間のデータ共有は、所有権の移譲を伴うメッセージパッシングによって行い、データ競合を原理的に排除する。 `{EliminateDataRace}`
- 割り込みが発生した際、その割り込みに関連付けられたタスクは強制的に割り込み状態へ遷移（ウェイクアップ）されなければならない。 `{InterruptWakeup}`
- ウェイクアップしたタスクは、自らHALの割り込みフラグを確認し、必要な処理を行う。 `{TaskPollInterruptFlag}`

## vSoC

- vSoCはwasm32のランタイムを持つ。浮動小数点の機能は実装しない。
- vSoCはvMMIOというMMIOを持つ。
- vSoCで複数のゲストを実行できるようにする。マルチコア対応はコアごとにハイパーバイザをアフィニティする構成。
  - ハイパーバイザ間のデバイスドライバの排他処理はデバイスドライバ層で行う。
- HALからCOOSに割り込みをかけ、ゲストのコンテキストスイッチ時に割り込みハンドラを呼び出す。
- JITコンパイラの基本方針はコンパイルレイテンシの最小化である。WASMバイナリは生成時に最適化済みであることを前提とし、実行時のデータフロー解析等は行わない。テンプレートをヒープに展開しパッチを当てる方式を採用する。基本的な算術演算を除き、vSoCのランタイムAPI呼び出しをコンパイルするのみとする。 `{LowLatencyJIT}`
- 高速なコンパイルにより、コードキャッシュの破棄と再生成のコストを抑え、小規模なキャッシュ領域での運用を可能にする。これにより、複雑なホットスポットプロファイラや多段JITを不要とする。 `{SimpleJITArchitecture}`
- JITコンパイラの出力するバイナリはPICであること。コンテキストへのポインタをレジスタに保持し、そこからデータにアクセスする。 `{PositionIndependentCode}` `{ContextPointerRegister}`

## システムコール

- システムコールは独自のシステムコールとする。
- システムコールはIPCで行われる。 `{IPCRouter}`
- IPCの経路はIPCルータが管理する。 `{IPCRouter}`

## HAL

- HALは独自仕様とする。
- プラグインとしてWASIラッパーを持つ。
- HALのバックエンドのドライバはベアメタル、Zephyr、Linuxを想定する。
- プロセス間通信はCSPを用いたIPCとする。

## 設定

- ヘッダファイル形式のコンフィグファイルを定義しその中のマクロで容量などは固定する。 `{ConfigurableSystem}`
- ヘッダファイル形式のコンフィグファイルを定義しその中のマクロでヒープサイズなどを固定する。 `{ConfigurableSystem}`
