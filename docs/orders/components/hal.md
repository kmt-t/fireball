# HAL

## 概要

vSoCからHALをIPCで呼び出し、ハードウェアへアクセスする。HALは独自仕様であるが、サービスとしてWASIがHALのラッパーが提供される。 `{IPCRouter}`

## 割り込みの仕組み

- 割り込みはフラグでインタープリタに通知する。 `{TaskPollInterruptFlag}`
- wasmゲストの割り込みハンドラは決め打ちの`__interrupt_handler`関数で定義される。
- 割り込み要因などは`__interrupt_handler`関数の引数に渡される。
- **安全性確保の方策**: 実行コンテキストの安全性を確保するため、HALは割り込み発生時にフラグ通知（およびタスクのウェイクアップ要求）のみを行い、実際の処理はインタープリタ側のPoll（`co_yield` 後のチェック）に委ねる。 `{Challenge_InterruptSafety}`

## 想定されるバックエンド

- HALは標準入出力、タイマーを最低限の機能とする。
  - 標準Cライブラリ、標準C++ライブラリで実装する。
- 想定されるバックエンドドライバは下記の通りである。
  - ベアメタル
  - Zephyr

## 想定されるデバイス

下記のようなもののデバイスドライバを用意する。

- UART
- USB
- I2C
- SPI
- ADC

## HALのAPI

下記のコマンドを持つ。vSoCはIPCでHALのAPIにアクセスする。 `{IPCRouter}`

- readコマンド
  - データを読み出す。
  - すべてブロックデバイスのためinfoコマンドでブロックサイズを取得する必要がある。
    - ブロックサイズが1のものをキャラクタデバイスとみなす。
- writeコマンド
  - データを書き込む。
  - すべてブロックデバイスのためinfoコマンドでブロックサイズを取得する必要がある。
    - ブロックサイズが1のものをキャラクタデバイスとみなす。
- seekコマンド
  - データを移動する。
  - ストリーミングデバイスには実装されない。
- ioctlコマンド
  - コマンドを実行する。
  - パラメータはIPCのKey-Value配列のため、voidポインタは用いない。 `{TypeSafeMessaging}`
- infoコマンド
  - デバイスの情報を取得する。
    - デバイスの名前。
    - リビジョン。
    - サポートするコマンド。
    - ブロックサイズ。
    - 通信に使うバッファの最大サイズ。
    - 通信に使うバッファの最大数。
- acquire_bufferコマンド
  - read/writeコマンドで使用するバッファを確保する。
  - 組み込みではバッファはデバイスドライバ側で確保する必要があるため。
- release_bufferコマンド
  - read/writeコマンドで使用するバッファを破棄する。
  - 組み込みではバッファはデバイスドライバ側で確保する必要があるため。

## 非機能制約達成のための方策

- **設定の固定**: デバイスの最大数やバッファサイズはコンパイル時に固定される。 `{ConfigurableSystem}`
