# JITコンパイラの理論と構想

## 1. 背景と仮説
組み込み環境（RAM 64KB）において、従来の最適化重視のJITはリソース消費が過大である。本プロジェクトでは、コンパイルコストを極小化する「Zero Compile Cost 定理」に基づき、最適化を省いた高速なコンパイルが、トータルの実行時間を短縮するという仮説を立てる。

## 2. 理論的裏付け

### 2.1 アルゴリズム解説: Copy-and-Patch with constexpr Encoder
1.  **テンプレート生成**: C++の `constexpr` エンコーダクラス（アセンブラ）を用いて、各WASM命令に対応するネイティブコードテンプレートをビルド時に生成する。
2.  **連結**: 実行時、WASMバイナリを走査し、対応するテンプレートをキャッシュ領域にコピーする。
3.  **コマンド再生成 (Patch)**: 即値やオフセットのパッチが必要な箇所は、テンプレート生成時と同じ `constexpr` エンコーダを実行時に使用し、正しい値で命令を**再生成**して上書きする。これにより、複雑なビット操作ロジックを排除する。

### 2.2 理論モデル: Zero Compile Cost
コンパイルコスト $C_{comp}$ を極小化することで、以下の不等式を成立させる：
$C_{comp} < (T_{interp} - T_{jit}) \times N$
ここで $N$ はループ回数。 $C_{comp} \approx 0$ であれば、極めて小さい $N$ でもJITの恩恵が得られる。

## 3. 検証とシミュレーション

### 3.1 キャッシュ管理シミュレーション
- **検証方法**: [`docs/orders/concept/jit_cache_sim.py`](../../orders/concept/jit_cache_sim.py) を用いた Active/Old ダブルバッファのヒット率シミュレーション。
- **結果**: ワーキングセットがパーティションサイズを25%超過しても、75%以上のヒット率を維持。
- **考察**: 小規模なキャッシュ（各2KB等）でも、世代管理によってスラッシングを抑制可能である。 `{JIT_DoubleBuffer_Cache}`

## 4. 設計へのフィードバック
- **反映先**: `{vSoC}` のJITエンジン設計に反映。
- **反映内容**:
