# 開発フェーズ

## 概要

`docs/architecture/overview.md`に従い、コンポーネントの開発スケジュールをフェーズ分けする。

## フェーズと日程

開発は以下の5つのフェーズに分割されている。

**スケジュール（2026年1月21日更新）:**
- 設計 Phase0（～2026年3月末）← 1ヶ月延長（2026/01/21合意）
- 実装1 Phase1（～2026年6月末）← 3ヶ月に縮小（2026/01/21合意）
- 実装2 Phase2（～2026年10月末）
- PoC Phase3（～2026年12月末）
- OSS Phase4（2027年1月～）

**Phase0延長の理由（2026/01/21 ワイガヤ合意）:**
- vSoCの設計を完璧に固めることを最優先
- 周辺コンポーネントは最小インターフェース定義でOK
- Phase1での手戻りを防ぎ、実装効率を最大化
- vSoCがクリティカルパスであり、後工程のボトルネック解消

## 設計 Phase0（～2026年3月末）

設計ドキュメントを作成し、設計の詳細を明確化する。**特にvSoCの設計を完璧に固める**ことを最優先とする。

### Phase0 サブフェーズ（2026/02/18更新）

**並行作業（Phase番号なし）:**
- 全設計ドキュメント（`docs/components/*.md`）の完成
- WIT契約（`@pre`, `@post`, `@inv`）の追加
- トレーサビリティマトリクス作成
- 表記揺れチェック

**Phase 0.7: Static DI & Build System**
- Harnessパターンの確定
- 静的DI機構（テンプレート、マクロ、アロケータ）
- WIT→C++自動生成（基本機能）
- Mesonビルドシステム

**Phase 0.75: Constexpr Verification & Code Gen Enhancement**
- コード生成ツールのconstexpr対応
- constexprメソッド特定（どのメソッドをconstexprにすべきか分類）
- コンパイル時計算検証（constexpr関数が実際にコンパイル時評価されるか確認）
- ルックアップテーブル生成（constexprによる静的テーブル生成の実証）

**Phase 0.8: vSoC TLA+ Verification**
- vSoC Interpreter: メモリ安全性、トラップ処理の正当性
- vMMIO: 許可テーブル検証、範囲チェック
- Loader: モジュールライフサイクル、依存解決
- リソース制約: RAM/SLOC予算の遵守検証

## 実装1 Phase1 (vSoC First)

- **vSoC (最優先)**
  - スタンドアロン・ビルド環境
  - wasmローダ
  - インタープリタ（算術・制御・メモリ）
  - JITコンパイラ
  - ベンチマーク・ハーネス
  - WAMR比較評価

## 実装2 Phase2（～2026年10月末、4ヶ月）

周辺コンポーネントの実装と統合。

- COOSカーネル（スケジューラ・CSP）

- HAL

- vSoC追加機能

  - デバッガ
