# BUG-0003 `k_life` がTier 3で終了しない

| 項目 | 内容 |
| :--- | :--- |
| 重大度 | 重大 |
| 状態 | 修正済み |
| 対象 | `runtime_engine`, `x64_jit` |
| 発見日 | 2026-09-19 |

## 1. 現象

大規模ワークロードの `k_life`（Game of Life）をTier 3で実行すると、終了しない。

## 2. 再現手順

```bash
timeout 90 .venv/Scripts/python.exe experiments/pysim/benchmarks/profile/bench_vtune_workload.py --phase suite_jit --kernel k_life:1
```

実測結果は、90秒でタイムアウトした（終了コード124）。出力は空である。

Tier 2では、同じカーネルが6単位で1.37秒である（実測）。1単位はこの約6分の1である。

## 3. 原因

BUG-0009と同じ原因である可能性が高い。ただし、`k_life` の停止そのものは、原因を直接確認していない。

同種のハングは、生成した制御フロー（シード17）で再現し、原因を確認した。ループを抜けた後の `br 0` が、古いループフレームをたどってループ先頭へ戻り、無限ループになった。

## 4. 影響

BUG-0001と同じである。加えて、ハングのため自動実行の安全装置（時間制限）が必要になる。

## 5. 修正と検証

BUG-0009の修正後、`k_life` は1単位と22単位の両方で終了し、wasmtimeと一致した。
