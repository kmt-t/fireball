# BUG-0007 ロガーURIがIPCサービステーブルに未登録である

| 項目 | 内容 |
| :--- | :--- |
| 重大度 | 低 |
| 状態 | 修正済み |
| 対象 | `ipc_router`, `platform_driver` |
| 発見日 | 2026-09-19 |

## 1. 現象

`fireball://hal/logger/0` は、WASI結線の `logger_uri` として定義されていた。しかし、IPCルータのサービステーブルには登録されていなかった。対応するロールもなかった。

そのため、この URI を担当する HAL ドライバを `System.start_hal_driver` で起動できなかった。

ロガーは、標準出力用ドライバと同じ出力バッファへ直接書いていた。この構成では、システムの警告ログがゲスト出力の途中に混入した。

## 2. 修正

- 初期修正で `HAL_LOGGER` とロガーURIを追加したが、ロガー用HALドライバは実際の出力経路に接続されていなかったため削除した。
- 現在は `System` 生成時に `FileLogSink` を直接注入する。`HAL_LOGGER` と `fireball://hal/logger/0` は現行のIPCサービス契約に含めず、ロール表は9x9である。
- `System.start_logger_driver` による出力先切り替えも廃止した。

## 3. 検証

- `TEST-IPCR-20` と `TEST-HAL-15` を追加した。
- pysim の単体テスト25スイートが通過した（2026-09-19 実測）。
- `check-src` の pysim グループと concepts グループが通過した。

## 4. 未見積もりの事項

この履歴に記載した初期実装の追加チャネル数とメモリ見積もりは、現行設計には適用しない。
