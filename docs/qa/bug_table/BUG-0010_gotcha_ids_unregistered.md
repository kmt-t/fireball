# BUG-0010 GOTCHA IDの定義・追跡不足（旧運用記録）

| 項目 | 内容 |
| :--- | :--- |
| 重大度 | 中 |
| 状態 | 解決済み（旧台帳方式は廃止） |
| 対象 | GOTCHA 定義元仕様書, テスト仕様書, 検証ゲート |
| 発見日 | 2026-09-19 |

## 1. 発見時の現象

発見時、文書とコードに現れるGOTCHA ID 77件のうち、運用台帳への登録は32件にとどまっていた。未登録45件のうち24件は設計書にも言及があり、残る21件はテスト仕様書とコードだけに現れていた。

未登録の内訳は、コンポーネント別に次のとおりである。

`INTP` 16、`CONT` 4、`LOG` 4、`COOS` 3、`JITC` 3、`SYS` 3、`HAL` 2、`IPCR` 2、`LOAD` 2、`MEM` 2、`DBG` 1、`INTR` 1、`SCHED` 1、`VSOC` 1

## 2. 発見時の規約との差

当時の `document_structure.md` は、キーワードIDと定義元所在を運用台帳で管理する方式を定めていた。設計書に定義がなく、台帳にもなかった21件は、その方式の条件を満たさなかった。

## 3. 当時の検証ゲートの限界

文書ゲート（`check-doc`）は、GOTCHA IDの登録漏れを検出しなかった。`GOTCHA-INTP-22` を波括弧あり・なしの両方で試したが、2026-09-19の実測では指摘が0件だった。

## 4. 発見時の処置

| 区分 | 処置 |
| :--- | :--- |
| 設計書に言及がある24件 | 設計書へインライン定義を置き、当時の台帳へ登録した。 |
| テスト仕様書にしかない21件 | 設計理由を設計書へ追加して登録するか、意味キーワードをやめてテストケースIDへ改める方針とした。 |
| 検証ゲート | GOTCHA IDの登録漏れを検査する案を記録した。 |

## 5. 発見時の修正記録

- 当時未登録だった43件を運用台帳へ追加した。各行には定義元、仕様概要、対応テストケースIDを記録した。
- 設計書から各GOTCHAを `<!-- traceability: ... -->` コメントで参照する方式にした。
- `GOTCHA-INTR-02` は実在しないIDだったため、バックログの誤記 `GOTCHA-INTP-02` へ改めた。
- テストケースIDを持たないGOTCHAには `-` を記録した（`INTP-18`、`INTP-20`、`JITC-06`、`HAL-02`、`HAL-03`）。
- 登録後、当時の運用台帳に載っていないGOTCHA IDが残っていないことを確認した。

## 6. 現行方式

キーワード一覧の手作業管理を終了し、正本の定義と同じセクションに `<!-- definition: &#123;Keyword&#125; -->`、参照側に `<!-- traceability: &#123;Keyword&#125; -->` を置く方式へ移行した。意味上の定義は仕様本文に置き、検証ゲートは文書内の定義宣言と参照を照合する。
