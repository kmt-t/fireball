# BUG-0010 GOTCHA IDの多くがキーワード台帳に登録されていない

| 項目 | 内容 |
| :--- | :--- |
| 重大度 | 中 |
| 状態 | 修正済み |
| 対象 | [`keyword_dictionary.md`](docs/architecture/keyword_dictionary.md), テスト仕様書, 検証ゲート |
| 発見日 | 2026-09-19 |

## 1. 現象

台帳（`keyword_dictionary.md`）に登録された GOTCHA ID は、全体の一部である。

| 区分 | 件数 |
| :--- | :---: |
| 文書とコードに現れる GOTCHA ID | 77 |
| 台帳に登録済み | 32 |
| 台帳に未登録 | 45 |
| 未登録のうち、設計書（`docs/components`、`docs/architecture`、`docs/specs`）にも言及がある | 24 |
| 未登録のうち、テスト仕様書とコードにしか現れない | 21 |

未登録の内訳は、コンポーネント別に次のとおりである。

`INTP` 16、`CONT` 4、`LOG` 4、`COOS` 3、`JITC` 3、`SYS` 3、`HAL` 2、`IPCR` 2、`LOAD` 2、`MEM` 2、`DBG` 1、`INTR` 1、`SCHED` 1、`VSOC` 1

例として、`GOTCHA-INTP` は 01〜06 だけが登録されている。07〜22 は、テスト仕様書の表に平文で置かれている。

## 2. 規約との差

ルール文書 `documentation-standards.md` は、`GOTCHA-<COMPONENT>-<連番>` を、設計理由と対応テストを持つものに限って許可する。

[`document_structure.md`](docs/architecture/document_structure.md) は、キーワードの正本を台帳と定める。

設計書に定義がなく、台帳にもないID（21件）は、この条件を満たさない。

## 3. 検証ゲートの限界

文書ゲート（`check-doc`）は、この状態を検出しない。`GOTCHA-INTP-22` を、波括弧あり（`{GOTCHA-INTP-22}`）となしの両方で試したが、どちらも指摘は0件だった（2026-09-19 実測）。

## 4. 処置案

| 区分 | 案 | 影響 |
| :--- | :--- | :--- |
| 設計書に言及がある24件 | 設計書へインライン定義を置き、台帳へ登録する | 設計書の追記と台帳の追記だけで済む。 |
| テスト仕様書にしかない21件 | (a) 設計書へ設計理由を書き、台帳へ登録する。(b) GOTCHA IDをやめ、テストケースID（`TEST-<コンポーネント>-<番号>`）へ改める | (a) は設計理由の執筆を要する。(b) は21件のID改番と、参照の更新を要する。 |
| 検証ゲート | GOTCHA IDが台帳に登録されていることを検査する | 未登録のIDが増えることを防ぐ。 |

## 5. 修正と検証

- 台帳へ、未登録だった43件を登録した。各行は、定義元の設計書、テスト仕様書、仕様概要、対応テストケースIDを持つ。
- 設計書は、各GOTCHAを見出し直下の `<!-- traceability: ... -->` コメントから参照する。定義は台帳の行に置く。
- `GOTCHA-INTR-02` は、実在しないIDだった。バックログの誤記であり、`GOTCHA-INTP-02` へ改めた。
- 台帳の設計の勘所の節に、Tier 1 Interfaceの節（4.2.2）を追加した。
- 登録後は、文書に現れるGOTCHA IDのすべてが台帳にある。
- 対応するテストケースIDを持たないGOTCHAは、`-` としている（`INTP-18`、`INTP-20`、`JITC-06`、`HAL-02`、`HAL-03`）。
- 文書ゲートは、GOTCHA IDの登録漏れを検出しない。この限界は変わっていない。
