# BUG-0011 JITの押し出し書き込みがオペランドスタックの容量を超える

| 項目 | 内容 |
| :--- | :--- |
| 重大度 | 高 |
| 状態 | 修正済み |
| 対象 | `x64_jit`, `runtime_engine`, `jit_cache` |
| 発見日 | 2026-09-19 |

## 1. 現象

JITは、TOS（R9）とNOS（R11）に載らない3個目以降の値を、共有オペランドスタックの `[R12 + スロット*4]` へ押し出す。この書き込み量に上限の検査がなかった。

トレースは、現在のスタック使用量に関係なく実行された。押し出しが容量を超えると、隣接する領域を破壊する。

## 2. 再現手順

深さ40の加算列を1ブロックで実行するトレースを、スタック使用量60ワードの状態から呼び出す（実測）。

- トレースは、ワード60から97までを書き込む。オペランドスタックの利用可能な容量は64ワードである。
- 深さ130では、ワード0から127までを書き込み、値領域の後続の `size` フィールドまで到達しうる。

Tier 2のインタープリタは、同じ状況でスタック容量の `assert` により停止する。JITだけが検査を素通りしていた。

## 3. 原因

コンパイラは、トレースが押し出す最大ワード数を記録していなかった。エンジンは、トレース呼び出しの前に容量を確認していなかった。

## 4. 修正と検証

- `compile_trace` は、押し出しの最大ワード数を数え、`JITTrace.stack_words` に記録する。ヘルパー呼び出しと結果の語数も含めた最大値である。
- `RuntimeEngine` は、トレースを呼ぶ前に、連鎖先を含めた最大の `stack_words` が容量に収まるか確認する。収まらない場合は、そのトレースを使わず、インタープリタが実行する。
- 単体検証は、`TEST-JITC-60`（押し出しと参照実装の一致、書き込み範囲が `[sp, sp+stack_words)` に収まること）と `TEST-JITC-61`（右にネストした式）である。
- 結合検証は、`TEST-JITR-61` である。インタープリタが容量超過で停止する状況で、JITを有効にしても同じ停止になることを確認する。
- 変異検査として、容量の確認を無効にした場合と、`stack_words` を記録しない場合で、それぞれテストが失敗することを確認した。
