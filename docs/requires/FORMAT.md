# 要求仕様書フォーマット定義

このドキュメントは、システムが満たすべき要求を定義するための標準フォーマットである。

## 1. 概要
この要求グループが解決しようとしている課題、および対象とする範囲を簡潔に記述する。

## 2. ユースケース
外部アクター（ユーザー、ハードウェア、他システム）との境界を明確にする。

### 2.1 ユースケース図
Mermaid記法を用いて、アクターとユースケースの関係を記述する。

### 2.2 主要シナリオ
最も重要な正常系の流れを記述する。

| ステップ | アクション | 期待される応答 |
| :--- | :--- | :--- |
| 1 | ユーザーがXXを行う | システムがYYを表示する |

## 3. 命題リスト
個別の要求事項を「命題」として定義する。機能要求と非機能要求に分け、さらに論理的なグループで分類する。

### 3.1 機能要求
システムが提供すべき機能に関する要求。

#### グループ名（例：WASM実行）
| キーワード | 内容 | 優先度 | 検証方法 |
| :--- | :--- | :--- | :--- |
| `{Requirement_Key}` | 要求の具体的な内容を記述する。 | 高/中/低 | テスト/レビュー/デモ |

### 3.2 非機能要求
システムの品質属性（性能、メモリ、安全性等）に関する要求。

#### グループ名（例：パフォーマンス）
| キーワード | 内容 | 優先度 | 検証方法 |
| :--- | :--- | :--- | :--- |
| `{Requirement_Key}` | 要求の具体的な内容を記述する。 | 高/中/低 | テスト/レビュー/デモ |

## 4. 制約事項
物理的、技術的、または運用上の制約を記述する。

- **メモリ制約**: RAM 64KB以内、等。
- **パフォーマンス制約**: 応答時間 XXms 以内、等。
- **互換性**: WASM MVP準拠、等。

## 5. 用語定義
この要求仕様内で使用される専門用語や略語を定義する。

## 6. 設計完了チェックリスト（網羅性確認）
要求定義が完了したとみなすためのチェックリスト。確認してチェックすること。

- [ ] すべての主要なアクターが特定されているか
- [ ] 正常系・異常系の主要なユースケースが網羅されているか
- [ ] 命題リストが機能・非機能で分類され、グループ化されているか
- [ ] 命題リストに一意のキーワード `{Keyword}` が割り当てられているか
- [ ] 非機能要求が具体的な数値や条件で定義されているか
- [ ] 検証方法が明示されているか
- [ ] 直交表（因子・水準）を用いた境界・組み合わせ条件の網羅性が検討されているか
