Native Interpreter BasicBlock search cache A/B — 2026-10-11

Purpose: isolate the dispatch-local PC-to-BasicBlock cache on a module with more than 10,000 BasicBlocks. The fixture executes a 250,000-iteration loop, then skips 3,334 cold blocks. AO-Bench is not used because its module does not stress a large BasicBlock index.
Conditions: CPU 2 pinned; 3 independent process trials; 3 warmup calls + 9 timed calls per variant and process; yield threshold 4096; NativeInterpreter.call() timed; module parsing and construction excluded. Variant order alternated per timed sample. The cache-off shared library was built from the same source with FB_CONF_NATIVE_BLOCK_SEARCH_CACHE=0.

Median-of-three-trials: cached=12.113 ms, no-cache=16.194 ms, speedup=1.337x. All three paired process trials favored the cache. This synthetic result demonstrates the lookup-heavy case and is not an AO-Bench or whole-application speedup claim.

The fixture returned successfully with no trap and no WASM results in all executions. The native interpreter and ABI behavior were also verified by the related QA suite.
